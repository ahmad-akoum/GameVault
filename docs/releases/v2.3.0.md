# GameVault V2.3.0 — candidate 2 (2.3.0+10)

Unpublished local testing candidate. No stable installation upgrade, tag, source
push, release or asset upload is authorized. Candidate 1 and its ZIP are preserved.

## Added
- Steam Refresh Installation across configured libraries with conservative status.
- Open Game Directory and Open EXE Location, plus saved build/timestamp details.
- A read-only Steam Update Center using explicit local app state: Update Available,
  Queued, Paused, Updating and current-session Downloading where supported.
- Unobtrusive top-left cover badges, amber profile status and separate Open in
  Steam controls; Steam alone manages downloads and installation.
- Latest-two Recent Sessions with View all sessions and Show less.

## Changed
- Restored pre-V2.2 HLTB search/retrieval, automatic lookup on explicitly selected
  imports, manual match selection and refresh. Saved data stays visible during
  failures. The startup disabled provider and fixed temporary warning are removed.
- Refresh uses the saved HLTB identity/title rather than silently changing editions.
- Recent sessions precede progress/collections; installation/tracking controls
  live in collapsible Game Settings.

## Fixed
- A stale installation folder no longer blocks Steam-mediated AppID launching.
  Installation refresh can repair library roots and exact relocated tracking paths.
- Narrow Expanded profile artwork uses a widescreen height cap; normal desktop
  sizes, independent cover/banner selections, and Crop/Fit remain intact.
- Small manifest reads do not rely on timestamp/size caching, avoiding missed
  same-size, same-timestamp state changes. Bounded content-log reads are cached.

## Known limitations
- HLTB's website protocol is unofficial and can change or reject requests. It
  uses an identifying GameVault user agent and no script inspection, alternate
  endpoint discovery on denial, proxies, account impersonation or challenge
  bypass. 401/403/429 and other failures remain explicit errors. Successful
  requests do not establish licensing, endorsement or distribution permission;
  the previous rights concern remains unresolved before any public release.
- The earlier 403 came from a simpler probe that did not reproduce the normal
  request contract; it did not prove the original adapter was unusable. The
  corrected adapter succeeds, but the server's precise earlier rejection rule
  is not claimed as identified.
- Steam's manifests/logs are internal saved state, not a supported real-time
  button API. Build mismatches or schedules alone never create update badges.
  Old running flags, missing files, unavailable drives, conflicting/unknown state
  and ambiguous installations remain Unknown. Closed Steam shows last-known
  evidence without live badges. No pending update recorded does not mean fully
  up to date. Queue position and exact schedule are not inferred.
- Real Bodycam relocation/launching, Explorer selection, current download
  transitions and final UI acceptance remain the owner's tests. Existing
  activity algorithms and personal session records were not changed.
