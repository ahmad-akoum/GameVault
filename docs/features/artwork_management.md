# Artwork selection and management — V2.2 Stage 2

Owner acceptance (2026-10-17): main import/apply/persistence/default-restore/Cancel and extra Steam-artwork checks passed; approved for progression to Stage 3. Remaining artwork edge cases are reserved for final V2.2 QA. This is not release approval.

## User behavior
Each game profile has **Manage Artwork** beside its profile-size controls. The dialog shows the current cover and banner, with independent role selection, thumbnails, a larger preview, Crop to fill / Fit entire image, Import image, Check Steam artwork, Restore Default, Apply and Cancel. Selecting a thumbnail or restoring a default only changes the preview until Apply. Apply saves the current role immediately; Cancel discards the remaining preview, not an earlier Apply. Switching roles discards that role's uncommitted preview. Enlarge preview uses the existing viewer.

Local imports are managed copies: moving/deleting the source file does not break the saved image. JPEG/PNG/WebP/still GIF/BMP are accepted when Flutter can decode them. Animated images are rejected. Limits are 16 MiB, 8192 pixels per side and 32 megapixels. Invalid, missing, unsupported and oversized inputs produce a message without replacing the selection. Missing/corrupt selected files render the existing placeholder; no personal image is automatically substituted or deleted.

## Data and implementation
- `lib/models/game.dart`: additive ArtworkPreferences stores original cover/banner paths, available saved choices, independent fit settings and explicit-choice flags. Legacy records initially retain their existing selected paths. The first Apply captures their defaults. VaultGame.profileArtworkPath freezes the old cover-as-banner fallback so changing a cover cannot change a profile that previously lacked a separate banner.
- `lib/services/artwork_store.dart`: ArtworkStore validates encoded dimensions and actually decodes the first frame at a bounded size, disposing temporary buffers/codecs. importImage writes a uniquely named, exclusively created managed copy without recompression. steamChoices checks existing Steam CDN endpoints only when requested, validates responses, deduplicates exact bytes and reuses immutable cache files. Network size/time limits bound each request; unavailable candidates are omitted. No network request happens during ordinary rendering.
- `lib/state/vault_controller.dart`: applyArtwork runs through the existing serialized mutation queue and saves selections with the latest session records. A failed save retains the previous in-memory selection. Metadata enrichment merges against current selections, including explicit empty defaults, so an in-flight refresh cannot replace a user's choice. Artwork Apply changes no game metadata or tracking settings.
- `lib/services/local_store.dart`: originals and choice lists use relative paths inside the vault, just like selected artwork. Copying a vault therefore preserves the links. The storage version remains additive version 2.
- `lib/services/metadata_provider.dart`: metadata refresh never rewrites an existing artwork cache file, including damaged files; repair is an explicit user choice rather than silent replacement.
- `lib/ui/artwork_manager.dart`, `details_page.dart`, `components.dart`: themed dialog, entry point, profile/banner and library/cover fit settings. Existing artwork provider equality, synchronous cache keys, physical-pixel decode sizing and cache buckets are unchanged. No refresh delay, extra image pinning or enlarged global cache is introduced.

Cancel can leave a newly imported/downloaded file in the private cache. It does not apply that file or change game metadata. Previously selected files are retained deliberately; automatic deletion/garbage collection is outside this stage.

## Sources and limits
The original cached image, previously saved choices and user imports are supported. Optional Steam checks use the same existing CDN source: library_600x900/header for covers and library_hero/header for banners. Missing routes, duplicates, bad responses and connectivity failures do not generate fictional choices. Filename dimensions are not trusted as source resolution. Current assets may offer one distinct image or none; there is no promise of historical/DLC/promotional variants, and no website scraping, credentials or new third-party API is introduced.

Steamworks describes the separate asset roles in [Library Assets](https://partner.steamgames.com/doc/store/assets/libraryassets) and [Store Graphical Assets](https://partner.steamgames.com/doc/store/assets/standard). These publishing specifications are not a blanket redistribution license. GameVault claims no endorsement or ownership; artwork stays in the user's local vault, outside source/releases. Users should import images they have permission to use. A general public-distribution license for game artwork is not asserted by this feature.

## Tooltip bug
The desktop title bar previously lived in MaterialApp.builder, alongside the Navigator. Its Tooltip widgets therefore had no Overlay ancestor within their lookup boundary. The old structure is reproduced in an automated test and raises the reported Debug assertion. Moving the title bar into MaterialApp.home puts it under the route's Overlay. The corrected title-bar Tooltip can be displayed in a widget test. The Debug assertion itself is absent in Release, but the old overlay structure was invalid there too; Release interaction was not separately tested. No existing release binary was rebuilt.

## Manual checklist
1. Run build/windows/x64/runner/Debug/gamevault.exe; confirm 2.2.0-dev.2 in Settings. Open a game profile and Manage Artwork. Verify existing cover/banner choices remain distinct.
2. Import a vertical image, preview it, switch fitting, Apply cover; verify the banner is unchanged. Import/apply a wide banner and verify the cover is unchanged. Delete/move the external source files, restart, and confirm both managed copies remain.
3. Restore each default separately and Apply. Preview a change then Cancel; verify no pending change was saved. Earlier applied changes should stay applied.
4. Refresh artwork/metadata and scan Steam libraries. Verify selections and fit settings survive, while metadata refresh still works normally. Check Steam artwork explicitly; inspect any returned options before applying. Offline/unavailable sources should leave existing selections intact.
5. Try a corrupt image and unsupported format; verify a helpful error and unchanged selection. Use only the development copy to test missing managed files; verify the placeholder and recovery by importing/selecting another image.
6. Check Compact/Comfortable/Expanded profiles, six presets/custom colors and Dark/Light/System. Hover the desktop window controls; no Overlay error should appear. Check preview zoom/close and dialog scrolling at smaller window sizes.
7. During CONTROL or S.T.A.L.K.E.R. 2, observe library covers across tracking refreshes and Alt+Tab. Confirm stable images and continued Stage 1 idle/resume behavior. No game/controller configuration needs changing for artwork management.
