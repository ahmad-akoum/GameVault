# Session statistics presentation — V2.2 Stage 3

## Behavior
Game-profile Recent sessions and Activity history share a compact session card with explicitly labeled Total, Active and Inactive durations; local start/end timestamps; the existing end reason or Running status. Profiles omit the repeated game title. Unknown activity shows Unknown labels. The dev.4 polish reduces card padding to 12 horizontal / 10 vertical pixels and the inter-card gap to six pixels, and removes the activity bar and its color legends at the owner’s request. Explicit duration labels remain accessible.

The profile's lifetime summary always distinguishes total, active and inactive time. Its small mode note says whether statistics use active or total time. Activity/Home summary cards use ACTIVE PLAYTIME / TOTAL SESSION TIME and ACTIVE TODAY / TOTAL TODAY according to the existing activity-adjusted setting. Activity's heading and ranking labels identify the selected mode. Existing seven-day chart values expose exact durations, with a tooltip for values too long for a chart label. A zero-active range now says no active playtime was recorded, rather than implying no sessions exist. No new dashboard or chart type is added.

## Source files and decisions
- `lib/ui/session_presentation.dart`: sessionDuration formats stored integer seconds without rounding: 61 → 1m 1s; 3601 → 1h 1s; 90061 → 25h 1m 1s. Zero components are omitted, so a historical value stored as exactly one minute stays 1m rather than acquiring a gratuitous 0s suffix. Hours never wrap at midnight. No duration is derived from wall-clock dates. sessionRange formats local dates/times and includes the end date when a session spans dates.
- The same file's SessionBreakdown is a read-only presentation adapter. Current records have nonnegative counters and matching daily allocations; those are sufficient evidence for an activity breakdown. Incomplete/inconsistent activity evidence returns nullable active/inactive values. A valid zero active counter with complete total allocations still means fully inactive, while an empty zero-duration record means no time observed. hasUnknownActivity prevents aggregate active summaries from silently representing incomplete history as confirmed zero activity.
- `lib/ui/activity_pages.dart`: SessionRow displays the shared text-only card. No proportional activity graph remains. ActivitySummary and StatisticsPage retain the existing sums, date buckets, ranking policy and display limits. When activity evidence is incomplete, affected active views conservatively display Unknown rather than a speculative number/proportion. This does not alter recorded values or tracker totals.
- `lib/ui/tracking_controls.dart`: uses exact formatting in the profile summary and shows recent-session rows without repeating the game title. Empty history has a useful prompt. Tracking buttons, settings, collections and progress behavior are unchanged.

The original whole-minute formatter discarded remainder seconds in the displayed components: for example, Total 1m, Active 40s and Inactive 21s looked inconsistent despite correct stored counters. Exact display formatting fixes that presentation problem. The original playtime helper remains unchanged for other callers. A new narrow-Activity test also exposed a five-pixel overflow when longer labels and weekday text wrapped in the fixed chart columns. Flexible value-label space and fitting compact weekday labels fix that layout issue without changing bar values or introducing animation.

## Preservation and limits
No edits were made to session detection/accounting, controller input, thresholds, foreground handling, model parsing/serialization, storage, artwork management or image providers. Existing active-time grace rules still apply; this UI does not redefine idle or inactive time. It does not estimate missing precision, reconstruct historical activity, import Steam hours or modify existing sessions.

Current storage validation requires explicit activity counters and matching day totals. This stage does not relax that validation: unreadable old records still follow existing recovery/refusal behavior. The Unknown presentation fallback safely handles incomplete data reaching the UI, but is not a migration/import mechanism. Entire active aggregate views may conservatively be unavailable when they contain incomplete evidence; full-session totals remain available. Local timestamps are labels and need not imply that every wall-clock second was credited through monitoring interruptions.

Session cards add no timer, animation, image decode or network request. Existing recent-session limits (five on profiles, paginated Activity history) remain. System mode uses the existing light/dark theme selection.

## Manual acceptance
1. Run the Debug development executable and confirm Settings shows 2.2.0-dev.4. Open profiles with short and longer sessions. Check Total = Active + Inactive using the exact displayed units; date/time and the saved end status should be readable.
2. Check zero/full inactivity cases if present. With no history, confirm the empty prompt. A session over 24 hours should keep accumulating hours rather than wrap. Missing historical activity must not be shown as a confirmed active/inactive split.
3. Check Compact/Comfortable/Expanded, all presets/custom colors, Dark/Light/System and a smaller window. Inspect duration labels and scrolling.
4. Toggle the existing activity-adjusted statistics setting. Confirm Activity/Home labels and ranking mode follow it, while each session's full breakdown remains unchanged. Restore your preferred setting afterward.
5. Confirm imported covers/banners and their fitting still persist. During a short game session, recheck idle/resume behavior and cover stability across Alt+Tab. End normally, restart the development app, and confirm the same session values persist.
